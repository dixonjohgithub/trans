01  Executive Summary & Tool Overview

These three tools are complementary, not interchangeable. Standardizing on one leaves value on the table; the goal is to route each kind of work to the tool suited for it. In one line each:

GitHub Copilot is the always-on default inside VS Code that speeds up everyday development for the whole team. Claude Code is the deep thinker — via the VS Code extension and command line — for work that needs careful reasoning across an entire codebase. Devin AI is the autonomous worker on its own platform for handing off well-scoped tasks to run start to finish.

Environment assumption: VS Code is the supported IDE and Claude Desktop is not in scope — Claude Code is used through its VS Code extension and command-line tool. Badges below show only the surfaces used in this environment.

02  Use Cases & Token Efficiency

Tokens are the units of work these tools consume — roughly, the amount of code and text a tool reads and writes to do a job. Two things drive token use: picking the tool suited to the task and how tightly the task is scoped. How much of the codebase a tool holds in view at once shapes both.

How much each tool holds in view at once ↑ top

GitHub Copilot

Focused slice

Reads a small, relevant portion of the project by default and widens only when a larger task calls for it. Naturally lean on tokens.

Claude Code

Very large view

Can hold a very large amount of the codebase in view in one session — enough to reason across a whole project. Powerful, but the more it holds, the more tokens it uses.

Devin AI

Managed automatically

Handles context on its own behind the scenes. No window to manage — it pulls in what a task needs, and its internal steps stay out of day-to-day token use.

General token-saving best practices

  • Match the tool to the job: use the lightest-touch tool that can do the work, and reserve heavyweight autonomous options for tasks that truly need them.
  • Scope tightly: a wide view is a ceiling, not a target — point tools at the files that matter, since everything held in view adds to token use.
  • Load context once, ask many times: keep related questions in one session instead of reloading the same code repeatedly.
  • Write clear briefs up front: complete instructions cut the clarification cycles that quietly multiply token use.
  • Offload long or repetitive work: let an autonomous agent run multi-step and bulk jobs rather than driving them interactively.
  • Keep guidance stable: consistent project and team instructions let tools reuse prior understanding instead of reprocessing it each time.

GitHub Copilot — detailed practices ↑ top

GitHub Copilot  native to VS Code; leanest on everyday, high-frequency work
Memory — user rootSet personal custom instructions in VS Code settings for individual style preferences. Highest priority; stays with the developer, not the repo.
Memory — project rootCommit .github/copilot-instructions.md for team-wide conventions (AGENTS.md also recognized). Keep it short and factual — only what's true for the whole repo.
Memory — folder / pathAdd .github/instructions/*.instructions.md with an applyTo glob (e.g. applyTo:"src/api/**"). Prefer several narrow files over one giant file.
Plan modeUse the built-in Plan chat mode (or a read-only custom *.chatmode.md) before agent mode edits. The cloud agent posts its plan on the PR for review first.
Scoping contextReference precisely with #file/#selection rather than broad @workspace. Use prompt files (*.prompt.md) for repeatable scoped tasks, and content exclusion to keep sensitive/irrelevant files out.
SubagentsNo first-class subagent system. Delegation is via the cloud coding agent and custom agents / chat modes; prompt files act as lightweight reusable specialists.
Parallel agentsAssign multiple issues to the cloud agent to run in parallel, each in its own isolated environment. In-editor agent mode is a single session.
MCP integrationsConfigure servers in .vscode/mcp.json (workspace) or repo settings (cloud agent). Enable only what a task needs — each server's tools add to context.
SecretsReference as ${input:my_secret} in mcp.json (prompted once, stored securely, never written to disk). For the cloud agent use dedicated Agents secrets (org/repo), prefix MCP secrets COPILOT_MCP_, and enable secret scanning to catch leaks before commit.
OtherStandardize workflows with prompt files & custom chat modes; use Copilot code review with custom instructions; choose the right model per task; enforce policies and content exclusion centrally.

Claude Code — detailed practices ↑ top

Claude Code  used via VS Code extension + command line; strongest at wide-context reasoning
Memory — user rootPut personal, cross-project defaults in ~/.claude/CLAUDE.md (workflow, preferred commands, global conventions). Keep it short so it doesn't crowd project context.
Memory — project rootCommit ./CLAUDE.md for team-shared architecture, conventions, and build/test commands. Write only what's true every session, keep it under ~150–200 lines, and point to detail rather than pasting it. Personal overrides go in CLAUDE.local.md (gitignored).
Memory — folder / subdirA subdirectory CLAUDE.md (e.g. frontend/CLAUDE.md) holds module-specific rules and loads lazily — only when Claude reads a file there — so a monorepo doesn't bloat context. Compose with @path imports.
Plan modeEnter plan mode (Shift+Tab) for large or ambiguous tasks — Claude investigates read-only and proposes a plan. Invest in the plan so implementation is “one-shot,” and review it before approving.
Scoping contextRun /clear between unrelated tasks and /compact for long sessions. Name specific files, keep memory files lean, offload research to subagents to keep the main context small, and route simpler work to a lighter model.
SubagentsDefine specialists in .claude/agents/*.md (frontmatter: name, description, tools, model, mcpServers, isolation). Each runs in its own isolated context and returns only a summary — ideal for research, verification, and review.
Parallel agentsLaunch multiple subagents at once; add isolation: worktree so each works in its own git worktree without collisions. They share the prompt cache, so fanning out is efficient. Worktrees/subdirs of one repo share a single auto-memory directory.
MCP integrationsAdd servers at user, project, or local scope; commit project servers in .mcp.json. Grant subagents only the mcpServers they need; keep the active set minimal.
SecretsNever put secrets in CLAUDE.md (it's committed). Use env vars / .env (gitignored), pass credentials to MCP servers via env, and lock down execution with /permissions allowlists, hooks, and settings.json allow/deny rules.
OtherAdd reusable slash commands in .claude/commands/; use hooks for deterministic gates (format, tests); run /review for structured review; and route models deliberately — lighter for routine work, strongest only when needed.

Devin AI — detailed practices ↑ top

Devin AI  runs on its own platform; best for long, hands-off, and parallel work
Memory — org / user rootUse Knowledge for general facts Devin should reference in every session — style guides, architecture, org conventions. Add once so Devin stops re-deriving context.
Memory — project / repoScope Knowledge to the repo, and invest in repo setup once: dependencies, test/lint/build commands, env, VPN, DB. Machine snapshots let every session start ready.
Memory — task levelCreate Playbooks for recurring tasks — a Playbook is like a custom system prompt for a repeated job. Reach for one whenever you repeat the same instructions.
Plan modeDevin drafts a plan before working. Review and edit it — especially for ambiguous work — before it proceeds. Clear specs up front reduce mid-task re-planning.
Scoping contextWrite tightly-scoped tickets with clear acceptance criteria and relevant file paths. Lean on Knowledge/Playbooks so Devin doesn't re-learn context each run.
SubagentsUse managed Devins: a lead session delegates sub-tasks to child Devins, each a full Devin with its own VM. The lead scopes, monitors, resolves conflicts, and compiles results.
Parallel agentsRun multiple sessions or managed Devins in parallel, each in an isolated VM — ideal for fanning out across independent tickets. Keep each task self-contained.
MCP integrationsConnect via the large MCP connector catalog plus 20+ native integrations (trackers, chat, source control, cloud & data services). Enable only what a workflow needs.
SecretsStore credentials in Devin's Secrets / environment-variable manager — never paste keys into the prompt. Secrets are scoped (personal/org) and auto-retrieved later; consider direnv in repo setup.
OtherFront-load environment setup (snapshots, test commands) so sessions start productive; always review Devin's PRs before merge; write clear tickets to minimize clarification loops; manage from the VS Code extension while work runs on the platform.
